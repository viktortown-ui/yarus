# Протокол проверки ЯРУС 1.0.0

Дата: 20 сентября 2026 года. Среда: Windows x64.

## Подтверждено

- Go 1.27.1: 23 серверных теста — успешно. Включены конкурентный расход,
  идемпотентность, конфликт пересчёта, роли, приглашения, повреждение журнала,
  disk failure, directory lock, миграция и ротация 30 backup‑файлов.
- Node.js: 40 тестов правил/кодов/PDF/миграции — успешно. Проверены QR‑fixtures,
  повёрнутые EAN/Code128, точные дробные количества, запрет отрицательного остатка,
  CSV, восстановление истории и отчётные строки.
- Двухклиентный live‑тест с настоящим `YARUS-server.exe`: сотрудник получил остаток
  владельца; повтор одной команды проведён ровно один раз; журнал, сессия и остаток
  сохранились после остановки и запуска сервера.
- Windows portable ZIP распакован в чистую временную папку и реально запущен.
  `/api/info` вернул 1.0.0, Win32 создал два окна WebView2, `yarus.journal` и профиль
  WebView2 появились именно внутри `data` этой папки.
- Windows использует официальный `WebView2Loader.dll` 1.0.4191.47. SHA‑256 loader:
  `c66e4a92fdc7a216118e43b7a5024ea2200e8c43f9310bf20d96a0084f82c5bc`.
- Android: стандартный Gradle/SDK release build и lintVital — успешно. APK и AAB
  подписаны одним RSA‑4096 ключом. `apksigner` подтвердил APK Signature Scheme v2/v3;
  `jarsigner` подтвердил AAB.
- APK metadata: package `ru.viktortown.yarus`, versionCode `2026092001`,
  versionName `1.0.0`, minSdk 24, target/compileSdk 36, только INTERNET и CAMERA.
- Manifest содержит локальный `YarusWidgetProvider`; release‑компиляция Java/resources
  и lint прошли, значения виджета передаются только во внутренние SharedPreferences.
- Android APK ZIP цел, содержит автономный HTML 1.0.0 с PDF‑модулем и без внешних CDN.
- APK установлен и запущен на эмуляторе Android 16 (1080×1920, density 420).
  Проверены первый запуск, учебный и личный склад, сохранение после принудительного
  закрытия/перезапуска и обновление тем же подписанным APK без потери данных.
- Нативные Android‑сценарии прошли: системный выбор файла, экспорт полной JSON‑копии,
  сохранение и визуальная проверка PDF A4, портретный/альбомный режим, выдача CAMERA,
  добавление системного виджета и переход из виджета обратно в ЯРУС.
- Изображение EAN‑13 выбрано через Android Photo Picker и реально распознано локально
  как `4601234567893`. Отдельная регрессия принудительно отключает старый
  `image.decode()`/object URL путь, из‑за которого WebView не читал системный URI.
- Playwright/Edge: интерфейс, учебные данные, телефон/планшет, QR‑этикетка и экспорт
  PDF — успешно; неперехваченных JavaScript‑ошибок нет.
- Созданы и проверены размеры 5 телефонных скриншотов 1080×1920 и 5 планшетных
  1600×2560. В каждом комплекте больше текущего минимума RuStore в 3 изображения.
- Пример PDF открыт `pypdf`, затем отрендерен Poppler: 1 страница A4, не зашифрован,
  таблица/валюта/кириллица/нижний колонтитул визуально корректны.

## Не выдаётся за проверенное

- Проверка проведена на эмуляторе, а не на конкретном телефоне/планшете владельца.
  Виртуальная камера Android 16 выдала разрешение, но не отдала WebView стабильный
  видеопоток; живая камера, фоновые ограничения конкретной прошивки и принтер всё ещё
  требуют короткой приёмки на физическом устройстве. Импорт кода из изображения уже
  проверен через настоящий Android Photo Picker.
- Приложение ещё не загружено в кабинет RuStore, package id не проверен кабинетом,
  модерация не пройдена. Подготовлен пакет, но публикация требует действий владельца.
  Для первой версии рекомендуется готовый APK. AAB дополнительно требует уникальный
  PEPK‑архив, который создаётся только после входа в кабинет; открытый PEM уже включён.
- Windows EXE не подписан Authenticode: возможен SmartScreen «Неизвестный издатель».
- Не проверялась синхронизация через реальный роутер/гостевую Wi‑Fi‑изоляцию и через
  интернет. Проверен настоящий loopback‑сервер; для LAN остаётся приёмка сети владельца.
- Не выполнялся юридический аудит политики конфиденциальности и не указан публичный
  e‑mail/HTTPS URL владельца.

Эти границы не мешают локальному pilot‑использованию с регулярными JSON‑копиями, но
до единственного производственного реестра нужна физическая приёмка именно на ваших
Android‑устройствах и тест восстановления из backup на отдельной копии данных.
