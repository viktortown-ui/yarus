# Протокол 0.10.0

ЯРУС 0.10.0 beta — ПРОТОКОЛ ПРОВЕРКИ И ГРАНИЦЫ ПРИЁМКИ

СТАТУС: исходники обновлены, Android APK и Windows x64 EXE собраны.
Это не заключение о готовности к промышленной эксплуатации и не гарантия отсутствия ошибок.

58 АВТОМАТИЧЕСКИХ ТЕСТОВ — ПРОШЛИ:
22 — сервер: атомарность, запрет минуса, конкурентные списания, повторы запросов,
перемещение, пересчёт, обратные записи, роли, приглашения, аутентификация, журнал,
восстановление после прерывания записи, отказ диска, бэкапы, CORS, блокировка папки,
миграция старого журнала с точной копией, сохранение QR-идентификатора и уникальность кода.
Запуск: go test -race -v ./... на Linux. Детектор гонок замечаний не сообщил.
11 — прежние правила клиентского складского ядра.
21 — коды: QR, EAN-13/EAN-8, базовый Code 128 на подготовленных изображениях,
повороты, часть искажений/размытия, контрольная цифра, принадлежность складу,
отказ для неверного формата, QR encode/decode round-trip.
4 — восстановление реального формата 0.9.1: количество 17 000 тысячных (17 шт),
поля товара, заводской код с ведущим нулём, история и места сохранены;
новый идентификатор создаётся один раз и сохраняется при повторном backup/restore.

ДОПОЛНИТЕЛЬНО ПРОВЕРЕНО:
- Интерфейс в Chromium: поиск/карточки/приход/ошибка нехватки/тема, отсутствие
  горизонтального переполнения на выбранных размерах телефона и планшета.
- Общий сканер: неизвестный EAN привязывается без изменения остатков; загруженное
  изображение открывает товар; QR товара заполняет форму без потери введённого
  количества; неверный склад отклоняется; URL из QR не открывается; viewer не
  получает кнопки записи; искусственный отказ доступа к камере объясняется.
- Размеры сканера: 360x780, 834x1112, 1112x834, 1440x1000, тёмная тема.
- Два тестовых UI-клиента с настоящим HTTP-сервером и дисковым журналом:
  изменение доступно второму клиенту, конфликт офлайн-черновика не исчезает,
  повтор после потерянного ответа не дублирует движение, перемещение согласовано.
- Реальные PDF из кнопки интерфейса: A4 содержит 12 одинаковых этикеток;
  отдельная страница 70x40 мм, границы корректны. PDF отрисованы; QR считан
  из растрового изображения полученного PDF. SVG экспортирован.
- APK: целостность ZIP/DEX/ресурсов, ссылки инструкций, регистры и outs_size,
  допустимые границы переходов, APK v2 RSA-SHA256 и полный digest.
  6 классов, 22 определённых метода. 84 — общее число ссылок в method_ids, не 84 теста.
- Тот же Android сертификат, package ru.viktortown.yarus, origin WebView и имя
  IndexedDB yarus-v1. Семь локальных скриптов и их CSP-хеши проверены; HTML
  в APK совпадает с общим упакованным клиентом. Лицензии встроены.
- Windows: выполнена кросс-сборка x64 GUI и console PE; GUI-оболочка содержит
  7 размеров иконки и asInvoker-манифест. Сервер использует прежнюю папку данных.

ВАЖНОЕ ОГРАНИЧЕНИЕ ТЕСТОВ:
Политика среды запрещает переход Chromium по URL; она не менялась и не обходилась.
UI монтировался через set_content, а клиентское постоянное хранилище заменялось
ЯВНЫМ адаптером в памяти. HTTP и файл журнала проверялись настоящим Go-сервером.
Моделирование отказа камеры — не проверка настоящей камеры.

НЕ ПРОВЕРЕНО ЗДЕСЬ:
Установка/обновление нового APK на физическом Android; полный ART verifier;

IndexedDB на телефоне и сохранение после перезапуска новой версии;
запуск EXE в настоящей Windows, WebView2 DLL/COM, новая папка профиля, веб-камера,
системный Save As; настоящая локальная сеть/брандмауэр/VPN; принтер/самоклейка.

СБОРКА И ТЕХНИЧЕСКИЙ ДОЛГ:
В этой среде нет Android SDK/D8 и Windows runtime. APK собран экспериментальным
автономным сборщиком DEX/AXML из исходников проекта; независимая структурная
проверка НЕ эквивалентна проверке Android. Java/Gradle проект включён для следующей
стандартной SDK-сборки. Windows host использует внутреннюю точку запуска
установленного WebView2 по схеме wailsapp/go-webview2; её совместимость требует
отдельной проверки. EXE без Authenticode. Выпуск в магазины не выполнялся.

БЕЗОПАСНОЕ ОБНОВЛЕНИЕ:
Сначала выгрузить JSON в старой версии и проверить наличие файла. Android обновлять
поверх старого приложения без удаления/очистки данных. Старый локальный Windows
склад в браузере переносить вручную через полную копию в новый профиль WebView2.
Общий сервер остановить перед заменой, отдельно скопировать каталог данных.
Не использовать beta как единственный реестр до физической приёмки.
