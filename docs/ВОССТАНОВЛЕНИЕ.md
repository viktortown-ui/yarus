# Данные, копии и восстановление ЯРУС 1.0.0

## Где лежат данные

В готовой переносимой Windows‑папке общий склад и локальный профиль находятся в
`data` рядом с `YARUS.exe`. Основной серверный файл — `data/yarus.journal`, копии —
`data/backups`. Не редактируйте журнал и не запускайте два процесса с одной папкой.
Перед копированием или переносом полностью закройте `YARUS.exe` и `YARUS-server.exe`.

Android и личный режим хранят данные в приватном профиле приложения. Удаление
приложения/его данных удалит склад, если нет внешней JSON‑копии.

## Нормальная схема копий

1. Через «Настройки → Выгрузить полную копию» сохраняйте JSON после важных изменений.
2. Держите минимум одну копию на другом диске/носителе. CSV не содержит полного
   состояния и истории, поэтому не заменяет JSON.
3. Общий сервер создаёт копию при старте непустого склада, раз в сутки и по кнопке
   владельца. Хранятся 30 последних успешно созданных копий.
4. Папка `data` и JSON содержат рабочие сведения; не отправляйте их посторонним.

## Восстановление общего сервера

1. Закройте все процессы ЯРУС.
2. Скопируйте всю текущую `data` в отдельное безопасное место.
3. Сохраните повреждённый `yarus.journal`, не удаляя его.
4. Выберите заведомо исправный файл из `data/backups`, скопируйте в `data` и назовите
   `yarus.journal`. Включите показ расширений, чтобы не получить двойное расширение.
5. Запустите ЯРУС. Повреждённая запись вызывает отказ запуска, а не тихое усечение.
6. Проверьте пользователей, последние движения и контрольные остатки. Изменения после
   времени копии восстановите по первичным документам, не повторяя операции вслепую.

Откат журнала откатывает также сессии, приглашения и отключения пользователей.

## Восстановление JSON

JSON восстанавливает локальный склад целиком и не объединяет его с текущим. Перед
заменой приложение сохраняет внутреннюю копию «до восстановления», но внешняя копия
надёжнее. JSON проверяется по формату и пересчётом истории. Импорт JSON в серверный
общий склад намеренно не автоматизирован: слияние двух журналов требует ручного
решения владельца.

## Пароль и ключ Android

Сброса пароля владельца через разработчика нет. Храните его в менеджере паролей.
Папка `PRIVATE-SIGNING-KEY` нужна только владельцу для будущих обновлений RuStore.
Не загружайте её в магазин, GitHub, облачную карточку или чат. Сделайте две защищённые
копии. Потеря ключа не удалит данные, но не позволит выпустить совместимое обновление
того же Android‑приложения.
