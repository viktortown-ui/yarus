# Архитектура ЯРУС 1.1.2

## Главный принцип

У общего склада всегда одно активное главное устройство. Оно принимает команды,
проверяет права, меняет остатки и присваивает порядковый номер. Клиенты хранят
последнюю подтверждённую копию для чтения, но не создают вторую независимую истину.

Главным устройством может быть:

- Windows-компьютер — рекомендуемый вариант для постоянно работающей команды;
- Android-телефон или планшет — локальный сервер работает только пока ЯРУС открыт.

Личный режим отдельный: это база одного устройства, без автоматической синхронизации.

## Общий код

`web/domain.js` содержит детерминированные правила товаров, мест, движений,
остатков и ролей. Один интерфейс и одни правила упаковываются в Windows WebView2 и
Android WebView. `server.go` повторяет критические серверные проверки независимо от
клиента. Android-главное устройство использует `web/host.js`, а Java-слой только
даёт защищённое хранение и локальный HTTP-шлюз.

## Синхронизация

Каждая команда имеет криптографически случайный id. Главное устройство записывает
результат один раз; повтор того же id возвращает уже сохранённый результат, а
другая команда с тем же id отвергается. При обрыве связи клиент оставляет явно
видимый черновик и повторяет его после восстановления связи.

Слияния двух самостоятельно изменённых баз нет. Это намеренно: автоматическое
слияние складских движений может удвоить приход или расход.

## Роли

| Роль | Возможности |
|---|---|
| Владелец | Всё, включая перенос главного устройства |
| Администратор | Каталог, места, движения, отмена, настройки, команда, копии; без переноса и смены владельца |
| Менеджер | Каталог, места, движения, просмотр цен |
| Кладовщик | Только приход, расход, перенос и пересчёт |
| Просмотр | Только подтверждённые доступные данные, цены скрыты |

Проверки выполняются и в интерфейсе, и на главном устройстве. Старое имя роли
`editor` читается как `manager` для совместимости с базами 1.0.0.

## Хранение

### Windows

- append-only `data/yarus.journal`;
- каждая запись AES-256-GCM, связана с предыдущей через аутентифицированные данные;
- отдельный случайный ключ `data/yarus.key`, защищён Windows DPAPI для текущего
  пользователя Windows;
- `fsync`, блокировка второго процесса, атомарная миграция старого открытого журнала;
- до 30 защищённых внутренних копий.

### Android-главное устройство

- приватный `host-state.yarus.enc`;
- AES-256-GCM, ключ неэкспортируемый и хранится Android Keystore;
- временный файл синхронизируется и атомарно переименовывается;
- одна защищённая внутренняя копия в день, до 30 копий.

Личный склад Android/Windows WebView хранится в IndexedDB профиля приложения.
Он не является общим сервером и не обещает шифрование отдельным ключом ЯРУС;
защита опирается на учётную запись/блокировку устройства. Для чувствительной
командной базы следует использовать общий режим и внешние защищённые копии.

В Android личный склад может дополнительно иметь пользовательский файл
`.yarus.json`, выбранный через системный Storage Access Framework. IndexedDB
остаётся основной атомарной рабочей копией, а внешний файл переписывается после
успешного локального изменения. URI хранится только в настройках приложения;
после переустановки файл остаётся на носителе, но пользователь выбирает его снова.
Файл не содержит паролей или токенов и не зашифрован.

## Перенос главного устройства

Владелец указывает имя нового устройства. Старое главное устройство фиксируется
как `retired` до создания файла и больше не принимает движения. Полное состояние,
включая пользователей и хеши паролей, шифруется в `.yarus`:

- PBKDF2-HMAC-SHA256, 310 000 итераций;
- случайная соль и nonce;
- AES-256-GCM;
- отдельный код из 20 символов (5 групп по 4);
- тип файла и идентификатор склада аутентифицированы.

Новый главный склад можно импортировать только на пустое устройство. Приглашения и
сессии сбрасываются, владелец получает новую локальную сессию.

## Сеть

Windows и Android слушают локальный HTTP-порт 8787 (Android при занятости выбирает
до 8797). HTTP допустим только в доверенной LAN. Для интернета требуется отдельный
HTTPS reverse proxy или VPN. Сервер ограничивает размеры запросов, проверяет JSON,
сессии, роли, версии объектов и происхождение браузерных запросов.

## Границы

Это не бухгалтерия и не ERP. Нет автоматического облака, разрешения конфликтов
двух главных баз, фонового Android-сервера, Data Matrix/GS1, партий, серий и FIFO.
