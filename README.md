# ЯРУС 0.10.0 beta — товары, места и движения

Это обновление общего проекта 0.9.1, а не отдельный несвязанный сканер.
Android телефон и планшет используют один APK. Windows x64 получил нативное
окно Win32/WebView2 с локальным интерфейсом. Linux поставляется как сервер.
Сборок macOS / iOS / iPadOS нет. Веб-интерфейс адаптивный, но браузер не является
обязательной оболочкой для Android и нового Windows-приложения.

## Что добавлено

- Камера, чтение изображения и поле USB/Bluetooth-сканера с вводом как с клавиатуры.
  Встроенные декодеры: QR, EAN-13, EAN-8, базовый Code 128 (без GS1/FNC/SHIFT).
  Камера включается по кнопке и останавливается после результата/закрытия/паузы.
- Поиск по коду; незнакомый код можно привязать к карточке или создать новый товар.
  Замена существующего заводского кода требует подтверждения. Один внешний код
  у карточки; внутренний QR не заменяет заводской штрихкод.
- QR товаров и мест хранения. Сканирование заполняет выбор, но не проводит движение.
- Этикетки 70×40 мм, PDF одной этикетки или до 12 одинаковых этикеток на A4, SVG кода.
  Не шаблон произвольной самоклейки и не драйвер термопринтера. Печать из PDF-программы.
- Понятное сообщение под количеством при недостаточном остатке; запрет отрицательных
  остатков сохранён и на клиенте, и на сервере.
- Мобильные формы в одну колонку, адаптация планшета/компьютера, тёмная тема сканера.
- Постоянный идентификатор склада в старом совместимом формате данных версии 1.
  Перед миграцией серверного журнала делается побайтовая резервная копия.

## Сначала сохраните данные

В старом ЯРУС: Настройки → Выгрузить полную копию → Сохранить файл.
CSV остатков не заменяет полную JSON-копию с историей. Не удаляйте старый Android
и не очищайте его данные. 0.10.0 подписан тем же сертификатом; package, origin
WebView и имя IndexedDB сохранены. Реальное обновление на устройстве ещё нужно проверить.

Windows: старый локальный склад в Edge/браузере НЕ появится автоматически в новом
профиле WebView2. Экспортируйте JSON из старой версии, затем восстановите его в
локальном режиме новой. Общий сервер использует прежний каталог данных:
`%LOCALAPPDATA%\Yarus\data`. Перед заменой EXE остановите старый сервер и скопируйте
весь каталог данных отдельно. Не запускайте старую и новую версии одновременно.

## Запуск для пользователя

Читайте `docs/НАЧАТЬ.html`. На Android — установить APK поверх 0.9.1.
Windows — полностью распаковать архив, запустить `YARUS.exe`; нужен WebView2 Runtime x64.
Интерфейс загружается с собственного локального сервера, без внешнего сайта.
Сервер работает, пока открыто окно. Отдельно, без интерфейса:
`YARUS-server.exe --headless`. Для служебного режима на Linux: `./yarus-server --headless`.

Не открывайте порт 8787 в интернет. HTTP допускается только в доверенной локальной
сети; для доступа из интернета нужен HTTPS reverse proxy. VPS здесь не развёрнут.
Персональные склады — отдельные наборы данных, не автоматически общий склад.

## Разработчику

`web/domain.js` — клиентские правила, количество в целых тысячных.
`server.go` — HTTP, роли, журнал с fsync, идемпотентность, конфликты версий.
`web/codes.js` — идентичность QR / внешние коды и 1D декодирование.
`web/scanner.js` — камера, привязка, заполнение формы, PDF/SVG этикетки.
`web/vendor` — локально включённые QR encoder/decoder; лицензии в поставке и интерфейсе.
`desktop_windows.go` — экспериментальная нативная Win32/WebView2 оболочка.
`android/` — Java/Gradle проект. `tools/build_android_offline.py` — использованный
автономный экспериментальный сборщик DEX/AXML/APK v2 без Android SDK.
Последний не заменяет D8/ART и испытания на устройствах. Ключи в исходники НЕ входят.

Сборка Linux / Windows серверов требует Go 1.23+ (сторонних Go-зависимостей нет).
Windows GUI: `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -H=windowsgui" -o dist/YARUS.exe .`
После неё: `python tools/pe_icon.py dist/YARUS.exe branding/YARUS.ico`.
На Windows готовый сценарий `tools/build_windows.ps1`.
`python tools/pack_web.py` собирает общий автономный HTML и активы Android.

Android offline builder: Python 3, cryptography, cairosvg; задайте YARUS_SIGNING_DIR
на каталог с оригинальными release-key.pem/release-cert.pem. Чужой/новый ключ не
обновит установленное приложение. Сборщик отказывается молча менять подпись.
Стандартный путь: открыть `android` в Android Studio, собрать Java/Gradle с SDK и
подписать тем же приватным ключом. Эта стандартная сборка в текущей среде не запускалась.

## Проверки

`go test -race -v ./...`
`node --test tests/domain.test.cjs tests/codes.test.cjs tests/upgrade.test.cjs`
`python tests/ui_smoke.py`
`python tests/codes_ui.py`
`python tests/client_sync.py`
`python tests/verify_apk.py dist/YARUS-0.10.0-android.apk`

Python UI-тестам нужны Playwright и Chromium. Их хранилище явно заменено адаптером
в памяти: политика среды запрещает переходы браузера по URL. Эта политика не
изменялась. HTTP и дисковый журнал проверены отдельно настоящим сервером. Камера
и нативные диалоги не подменяются утверждением, что были проверены на телефоне.
Результаты и ограничения: `docs/ПРОВЕРКИ.md` и текстовые протоколы в docs.

## Ограничения перед реальным использованием

Это закрытая beta. Нативные APK и EXE собраны, но в настоящих Android/Windows здесь
не запущены; камера/разрешения/диалоги/печать/обновление должны пройти приёмку.
Windows host использует установленный WebView2 и его внутреннюю точку запуска,
поэтому совместимость конкретной версии Runtime тоже требует проверки.
Не используйте beta как единственный реестр. Нужны внешние резервные копии и
параллельный проверенный учёт до завершения испытаний. Склад не шифруется приложением.
Это не бухгалтерия, не FIFO/средневзвешенная себестоимость, не маркировка и не ERP.
Нет GS1/Data Matrix, серий/партий, резервов, движения упаковка→единица, группового
сканирования с авторасходом, массовой печати разных карточек и слияния независимых
локальных складов. Перенос серверного журнала — не импорт локального JSON в сервер.
Старые пределы сохранены: 5000 товаров, 200 мест, CSV-импорт до 500 строк за раз.
